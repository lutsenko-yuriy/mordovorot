# GH-74: Solvable boards on odd sizes and unsolvable-save handling

## Notes

- 2026-10-15: Some classes are getting too big — e.g. `TuiView.kt` (~450 lines), `ViewImpl.kt` (~360), `ViewModelImpl.kt` (~380). Worth a dedicated split/refactor follow-up ticket.
- 2026-10-15: Console mode is rarely used by the user. Worth reconsidering how much effort goes into keeping console parity with the TUI (deprioritise, simplify, or drop it) — a follow-up decision, not in GH-74's scope.

## Debrief summary

### 2026-10-15

**What went well**
- Caught the unsolvable-board bug before the game went public: odd-sized boards could be shuffled into a state no sequence of shifts solves.
- The split into a scenarios WU, then WU1 (solvable shuffle + listing mark), then WU2 (repair / new game / exit) shipped cleanly, with no rework between WUs.
- Review and audit each found one real issue, both fixed in-PR: an undocumented `ExitRequestedException` on the `ViewModel` interface, and repair rewriting a save before checking it could load.

**What was hard or surprising**
- Nothing blocked this ticket, but `TuiView`, `ViewModelImpl` and `ViewImpl` have grown large (~360-450 lines). Not a problem yet, but a general worry that will hit later.
- Console mode is rarely used, yet every feature still pays for full console parity.

**What to change**
- Follow-up tickets: #78 (split oversized classes) and #79 (decide the future of console mode).
- Added a ~300-line file-size guideline to `docs/CODE_STYLE.md` (explicitly a guideline, not a hard limit), and a matching 🟡 "File size" check to the `review` skill.
