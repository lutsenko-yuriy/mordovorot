# GH-218: Run Mordie's search in a Web Worker in the browser client

## Notes

## Debrief summary

### 2026-11-01

**What went well**
- The brief, the plan and decisions D1 to D8 were settled before any code, and the worker went in as planned: a `:web:worker` module, `SearchProtocol` in `:shared:mordie`, `WorkerMordieSearch` behind the existing `MordieSearch` seam.
- Review and audit found only one real issue (the copy step could ship a stale file). The audit ran the worker in headless Chrome. The hidden-tab check in Firefox passed: N went from 12 to 13 with the tab hidden.

**What was hard or surprising**
- The dev server returned 404 for `mordie-worker.js`, so Mordie stayed at 0 moves and the player's win read "I was still at 0 moves". `serve` moves every project's build directory (GH-124), and the first copy step resolved the worker's output path too early, so it found no source. The fix was to have the worker project write into `:web`'s resources.
- Only the production distribution, the harness and a cold load were tested, and the audit tested the same path. Nobody ran the dev server until the user tried the change.

**What to change**
- `docs/workflows/FEATURE.md` step 10.0 now says to smoke-test `:web:serve -t` when a PR changes how the web client is built or packaged.
- Left open on the PR: Safari on the Mac, iOS Safari (a 4x4 with save, load and Give Up), Chrome's hidden-worker behaviour, and the page-delay measurement on 5x5 (the GH-211 scratch page is gone).
