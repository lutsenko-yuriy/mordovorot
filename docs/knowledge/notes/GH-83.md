# GH-83: Mordie: a computer opponent racing the player to the shortest solution

## Notes

### 2026-10-17

These amendments were recorded after the fact, during the debrief. Each one changed a rule in the ticket or the approved plan.

**Amendment: a fourth ending, MACHINE (planning)**
- **Old rule:** three endings - player won, matched, Mordie won.
- **New rule:** when the player's M is below Mordie's found N, the ending is `I made N moves and you made M moves! Are you a machine?` (`mordie_result: machine`). Only a hand-edited save can produce it.

**Amendment: singular "1 move" (planning)**
- Every count in Mordie's lines and endings reads `1 move`, not `1 moves`.

**Amendment: no legacy-save analytics flag (analytics/planning)**
- The plan considered a flag for games loaded from saves made before GH-83. It was dropped.

**Amendment: Mordie sits out a loaded board that already has moves (WU3 audit, PR #88)**
- **Old rule** (ticket and plan): a save with no Mordie data (from before GH-83, or a GH-74 Repair) makes the loaded board the original, and Mordie starts fresh with the move count kept.
- **New rule:** Mordie starts fresh only when `moveCount == 0`. Otherwise it is cleared: no line, the `Congratulations ✓` title, and no Mordie props on `board_solved`.
- **Why:** Mordie's N would cover only the moves after the load, while the player's M covers the whole game, so the comparison would be wrong rather than just slightly unfair.
- This rule was discussed in the brief, the plan and WU3, and the outcome differed each time; that is what the `MULTI_WU.md` amendment rule now prevents. Issue comment 6225533758.

**Amendment: skip a progress window with no news (manual test, PR #89)**
- A progress window (shifts 20-24, 40-44, and so on) stays empty when N equals the last N Mordie told the player. That is its last progress line, 0 for a new game, or the saved N after a load.

**Amendment: no blank row between `Moves:` and Mordie (manual test, PR #89)**
- The user suggested a blank row there, then dropped it. On 80x24 at 5x5 in keyboard mode, it would have pushed the controls hint off-screen.

**Amendment: centering counts the rows below the toolbar (WU4)**
- `BoardLayout` now centers the board with the mode row, the message and the hint counted (`BELOW_TOOLBAR`). Without this, the 3 reserved Mordie rows pushed the hint off a 24-row terminal at 5x5.

## Debrief summary

### 2026-10-17

**What went well**
- The planning prototype settled the solver design (exact IDA* in the GH-62 move metric) up front. The user didn't need to touch the solving mechanism and will study the material (chats and plan) separately.
- Five PRs (#85-#89) landed with review/audit rounds that found real issues early, such as the WU3 sit-out case.

**What was hard or surprising**
- Thinking the ticket through up front took a lot of effort. That is expected work, not an impediment.
- The rule for legacy and repaired saves was discussed three times (brief, plan, WU3), and the decision changed each time. No single place recorded the current rule.

**What to change**
- `MULTI_WU.md`: a WU that changes a ticket or plan rule records it at once as a dated `**Amendment:**` entry in the ticket's knowledge note, plus a PM comment. Later WUs read those amendments before raising the rule again.
