# GH-274: Friendlier wording of the game's text

## Notes

### 2026-11-16: Research-WU, localization without Compose

Question: how a Kotlin Multiplatform project with a plain-DOM Kotlin/JS client localizes its texts, to confirm D2 (an interface per area with an English `object`, keys as members, counts as `Int` arguments) and D3 (one `texts()` accessor). Target languages for GH-275: English, German and Russian; others later if needed.

**Evidence**
- Lyricist (github.com/adrielcafe/lyricist, 810 stars, release 1.9.0 on 2026-07-21): strings declared as an interface or class with one instance per language; plurals and arguments are lambdas. Its generated accessors are Compose-only, but it documents a path for other toolkits (a language-to-strings map, with your own refresh). This is the nearest precedent for D2.
- i18n4k (111 stars, v0.11.2): properties files plus a Gradle plugin that generates a Kotlin `object`; targets JS and the JVM.
- moko-resources (1353 stars, 0.27.1): needs its own Gradle plugin, Gradle 8.4+ and Kotlin 2.1+; strings in XML; on JS, JSON bundled by webpack. Heavy for this project.
- Compose resources: outside composables, strings come only from suspend functions, which does not suit a synchronous `texts()`.
- CLDR plural categories: English and German `one`/`other`; Russian `one`/`few`/`many`/`other` (1 ход, 2 хода, 5 ходов). Microsoft's localization guidance: whole sentences with placeholders, since fragments cannot be reordered, and declension depends on the sentence.
- Weblate supports about 50 formats (PO, XLIFF, JSON, properties, Fluent, Compose and moko resources) but not Kotlin source.

**Not found:** any report of these libraries in a plain Kotlin/JS DOM client; evidence that non-programmers translate from a code interface plus a text snapshot; whether Weblate or Crowdin can import a key-to-text file; a source on inserting inflected names into Russian software messages.

**Synthesis**
- D2 holds: a function of an `Int` per language covers English, German and Russian plurals, needs no Gradle plugin or Compose runtime, and has Lyricist as a maintained precedent.
- D3 holds: one accessor, as in Lyricist's non-Compose path.
- Amendment for WU1: `english.txt` is a stable key-to-text file, so GH-275 can export it to a standard format (PO or XLIFF) for translators.
- Case risk is limited to inserting a save name into a sentence; keep names quoted and out of inflected sentences.

**For GH-275**
- How translators work (a data-file export, or Kotlin edited by a programmer), which language is the default, and the language switch.
- The Controls list's space-aligned columns, `lang="en"`, and the plural forms Russian needs for each counted text.

## Debrief summary

### 2026-11-16

**What went well**
- Running WU1 (move the texts) and WU2 (tests to keys) under REFACTOR-style autonomy kept them quick; WU3's rewording diff then stayed small.
- Reviewing the wording as one `english.txt` diff, old line next to new, made the approval easy.
- Filling in the WU0 scenarios last, once the texts existed, worked.
- The review and the audit both caught the same save-error bug (the message chosen by exception type); that is what they are for.

**What was hard or surprising**
- The split was bigger than the first impression: putting the texts into their own module made GH-274 carry the groundwork GH-275 needs. Once the size was known it was fine, so only the first impression was off.

**What to change**
- Nothing in the workflow, skills or docs.
