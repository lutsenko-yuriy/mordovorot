# GH-148: Web on phones in landscape: fit the whole game on one screen, no scrolling

## Notes

## Debrief summary

### 2026-10-24

**What went well**
- `/plan` measured master before proposing a fix, and found that the panel, not the board, made the wide page too tall. It also found that the 408px/624px `--beside` literals pushed the board off narrow screens. Every decision (D1–D7) took the recommendation.
- Measuring with the harness, not guessing, drove both tunings from the plan: the 9.5rem steps column (at 9rem, longer `Row` steps scrolled by a pixel) and the SE's under-600px gaps. Measurements also decided the audit's `min-height` suggestion: it made 568×220 scroll, so it was declined.
- Review's file-size finding produced `fit.css`. Re-measuring after the move gave the same positions at every size.
- The user checked the change on an iPhone (Safari, Firefox) and on desktop before the PR opened. Everything looked fine.

**What was hard or surprising**
- `serve_lan.sh` from GH-147 failed under macOS's bash 3.2: an apostrophe inside `${var:-...}` reads as an opening quote. It was fixed on this branch.
- The phone's browser autocompleted an old address (`/mouse/`) and got a 404. Both surprises were fixed quickly, so the user was fine with them.

**What to change**
- No workflow changes. `serve_lan.sh` now prints a QR code for the phone's camera when `qrencode` is installed (the user's idea), so the browser can't swap in an older address.
