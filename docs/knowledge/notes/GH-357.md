# GH-357: Installable web app: manifest and icons (PWA)

## Notes

## Debrief summary

### 2026-11-27

**What went well**
- The offline half already existed (GH-262), so the ticket shrank to a manifest, icons and page tags, and the offline worker needed no change: it lists everything `jsProcessResources` outputs.
- The tests could be written without a build machine: the pixel positions `AppIconsTest` expects were checked against the committed PNGs with a separate script, and the first CI run was green. A draft PR right after the first push gave CI as the first compile and test run.
- The audit found a defect no test covered: a manifest `id` is parsed against the origin of `start_url`, so `./` was the whole `github.io` user origin, and the `id` can't change after release. It was fixed while that was still free (`mordovorot`), and ADR-0007 records why.
- The plan's ten decisions were each shown with options and a recommendation and approved together.

**What was hard or surprising**
- My first answer about PWAs, before the ticket, missed that GH-262 had already shipped offline play and the update notice; it surfaced while reading the code for the brief.
- Installing differs per platform: an Apple install (Safari on iPhone, iPad and Mac) keeps its own storage and starts with no saves, and Firefox and Chrome on iOS run on Safari's engine, so installing and offline play there are uncertain. Neither could be checked here; both are on the PR's manual checklist.
- The container can't build, so the headless install checks and the phone check could not run before the PR.

**What to change**
- No workflow or skill changes.
- Follow-ups ticketed: GH-359 (research: app store listings) and GH-360 (an install link and hint on the page).
