## Notes

## Debrief summary

### 2026-10-17

**What went well**
- Re-briefing the ticket before planning. It predated GH-42/GH-78/GH-79/GH-83, so its description and the old plan named `Presenter`/`ConsolePresenter`/`PresenterView`, which no longer exist. The fresh `/brief` set a different boundary: five modules, with Exit and all session control terminal-only.
- The REFACTOR run shipped three WUs (#104, #105, #106) with 586 tests unchanged in count, all moves as 100% renames with history intact, and a compile-only `js(IR)` guard that makes JVM-only APIs in shared code fail the build.

**What was hard or surprising**
- The WU2 ship subagent was denied `git add` by the permission rules. The session stopped to ask how to proceed, and nothing alerted the user, so the stall went unnoticed until they checked in. Habit Loop has an alert hook (HAB-162) that would have fired on that `Stop`; mordovorot and the YAB template have none.
- `Workflow: REFACTOR` was approved without the user noticing it had been proposed. It was "D7", the last of seven technical decisions, and "approve the plan" covered all seven.
- The plan agent and the audit agent were each cut off once by API usage limits and had to be resumed.
- `./gradlew test` at the root silently skips KMP subprojects' `jvmTest`; only `check`/`build` run them. The documented test command moved to `./gradlew check` in WU2, not WU3, so the docs were never wrong between merges.
- One plan checklist item assumed F7 switches modes while a dialog is open. It doesn't, on master either; the spec never promised it.

**What to change**
- `skills/design/plan/SKILL.md`: propose REFACTOR at the top of the plan and ask about it as its own question, never as one decision in a list.
- `docs/workflows/FEATURE.md` step 1.1: re-run `/brief` when a ticket names code or behaviour that has changed since it was written; any earlier plan is then superseded.
- Follow-up tickets: mordovorot #107 (port the alert hook), YAB #32 (ship it in the template), YAB #33 (propose an adopter's workflow changes back to YAB), YAB #34 (sync an adopter with upstream YAB), mordovorot #103 (run the shared modules on a real JS target).
- Open: whether REFACTOR's autonomy fits, given the user stepped in during development anyway. To revisit on the next REFACTOR ticket.
