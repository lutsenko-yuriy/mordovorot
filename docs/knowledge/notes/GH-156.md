## Debrief summary

### 2026-10-25

**What went well**
- Running the new tool on master against itself caught real noise early: under load, 15px scrollbar-width boxes and solution screens not reached. Rerunning alone cleared both, and the README now says so.
- After trying the tool, the agent proposed improvements and built them: the branch bundle is always built, same-selector elements are numbered, and repeated changes fold into one entry. The user wants to keep this.

**What was hard or surprising**
- Folding the follow-ups into the open PR cost two extra review rounds (three in all). The PR grew bigger than expected but stayed easy to follow; the extra rounds were the real cost.
- The follow-ups were described in one line each and sounded small next to the ticket. In review they were new logic, a new build step and a seven-file rename.

**What to change**
- When offering fold-in or follow-up ticket, size each item the way review will see it: new logic or not, roughly how many lines and files, and whether it needs another review round (`FEATURE.md` step 3.2, "Sizing the choice").
