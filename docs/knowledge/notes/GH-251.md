# GH-251: Delete saves from the Load and restore dialogs

## Notes

- 2026-11-06: For debrief: we need ways to test while the user is away from the computer, e.g. a cloud host (DigitalOcean) serving the branch's build.
- 2026-11-06: For debrief: we need an environment where the agent can build a KMP project (local Gradle is blocked by Maven Central 429 here, so CI is the only compile/test run and the headless keys check and layout measurement can't run), or a stack to migrate to from KMP.

## Debrief summary

### 2026-11-06

**What went well**
- The split into a contract WU (storage, viewmodel, analytics) and a UI WU kept the web diff to the dialogs and focus.
- Drafted scenarios first (WU0) gave the UI WU a checklist: all 12 went green on the first full CI run.
- The review and audit round found a real phone-layout problem (long save names pushed the trash icon out of the dialog), a two-tab startup gap, and a focus hazard (a stray Enter loading a save over the game), all fixed or decided before merge.

**What was hard or surprising**
- Being remote was the biggest drag. The agent's container can't run Gradle (Maven Central 429), so CI was the only compile and test run, and the headless keys check and layout measurement could not run. The owner could not try the build on a phone either.
- The first CI run caught an ARIA boundary test (`A11yBoundaryTest`) that a local run would have shown at once.

**What to change**
- Open the PR as a draft right after the first push to get a CI compile, and say in it which checks could not run (FEATURE.md step 10.0).
- Research a way to build, check and preview a branch while away from the computer: GH-255.
- Add delete-flow cases to `keys_check.sh` and measure a long save name at phone sizes once there is a bundle to open (checkup ledger, Carried in).
