# GH-225: Mordie plays 6x6 to 9x9

## Notes

## Debrief summary

### 2026-11-02

**What went well**
- The plan measured the fast solver before any code: 130 to 340 moves on 6x6 to 9x9, well under a millisecond, and the exact search rules out only 13 to 19 moves in 3 s. That settled "is it fast enough" without a Research-WU.
- The PR removed more than it added in production code (about 50 lines out of five files), and the sit-out came out cleanly because GH-83's rule for a played-on save already covered the one case still needing it.
- The phone-size harness reached the 6x6 and 9x9 solution screens for the first time and showed two real layout limits (320x568 portrait, 568x320 landscape) that the user then had folded into the PR.
- The audit found nothing; the user's own run in the browser found nothing either.

**What was hard or surprising**
- The shared board stops at 6x6 (`BoardSize` 3 to 6; 7x7 to 9x9 live in the web client), so the viewmodel tests could only cover 6x6 and the 9x9 cases are web scenarios and a solver test.
- `:web:serve -t` started no server when run from the agent's shell (nothing on 8080); the built bundle served by a static server stood in for the user's try-out.
- The 5x5 solution screen on a landscape SE already overflowed on master; the harness had never reached it before GH-222.
- A planning-step commit landed on local `master` by mistake and was moved to the feature branch before anything was pushed.

**What to change**
- Nothing; no workflow or skill files changed.
