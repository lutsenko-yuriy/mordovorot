# GH-153: Split the web client's styles.css into layout, dialog and solution-screen sheets

## Notes

## Debrief summary

### 2026-10-24

**What went well**
- The user likes the code getting clearer. `styles.css` went from 659 lines to four sheets: styles (333), board (128), dialogs (125) and solution (80). Every rule moved verbatim.
- `/plan` found the one place where the winner depends on source order. The tall fit's `.steps` max-height beats the base `.steps` only by coming later, so both went into `solution.css` in that order, with a test pinning it. `/plan` also flagged that the three-sheet split couldn't meet the ~400-line limit, so `board.css` was added.
- The REFACTOR workflow ran from plan approval to the PR with no questions. Review found one stale section header, fixed; audit made one caching suggestion, declined. Round 2 was clean.
- The evidence that nothing changed: a scratch script compared about 800k computed-style properties against master, and `measure.sh --baseline` compared 112 case pairs. The only differences were the new `<link>` tags, a fade-in caught partway, and solution-screen positions that also vary between master's own runs.

**What was hard or surprising**
- The computed-style dumps differed as strings on every element but on none as property maps: Chrome lists properties in a different order when the sheets differ. Seeding `Math.random` was needed to get the same scramble in both bundles.

**What to change**
- The computed-style diff becomes a committed tool next to `measure.sh`: GH-156, with the scratch version's full recipe. No workflow file changes in this debrief.
