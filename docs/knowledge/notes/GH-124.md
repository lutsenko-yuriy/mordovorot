# GH-124: Web dev server: rebuild on change, and run alongside builds

## Notes

## Debrief summary

### 2026-10-18

**What went well**
- Quick, and fully autonomous under REFACTOR (one WU): from plan approval to the final PR, the user was asked nothing. The user tested `./gradlew :web:serve -t` and confirmed it works.
- The plan's experiments found both causes before any code was written: the shared Kotlin compile daemon's 512 MB heap (fixed with `kotlin.daemon.jvmargs=-Xmx2g`), and two builds writing the same task outputs (fixed with a separate build directory for `serve`).

**What was hard or surprising**
- A build script can't turn on continuous build: `-t` must be on the command line, so a bare `serve` now fails fast with a hint (`settings.gradle.kts`).
- Audit round 1 found that `./gradlew clean` deleted `build/serve` under a running server. Moving serve's outputs to `build-serve/` (outside `build/`) fixed it.
- The user's own server held port 8080 the whole time, so every server check ran in a scratch worktree on another port (a `webpack.config.d/port.js` override), and processes were stopped by PID, never with `./gradlew --stop`.

**What to change**
- Nothing, per the user.
