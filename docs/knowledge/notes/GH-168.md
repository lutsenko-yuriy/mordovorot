# GH-168: Web: larger text without browser zoom

## Notes

- 2026-10-28: The glossary (docs/GLOSSARY.md) keeps growing; split it into several glossaries, one per domain (e.g. core game, web client, terminal, accessibility). Raise at the GH-168 debrief. This should also become a ticket for the YAB-dev repo (the workflow template), so the split applies to projects built on it.
- 2026-10-28: Research-WU findings (bounded, cited check):
  - **Headless Chrome (verified locally):** a throwaway `--user-data-dir` whose `Default/Preferences` holds `{"webkit":{"webprefs":{"default_font_size":24}}}` gives `html` a computed 24px and `1rem` = 24px; a fresh profile gives 16px. WU1's harness option can use this.
  - **Android Chrome:** without opt-in, the OS text size doesn't reach page text ("nothing happens"). `<meta name="text-scale" content="scale">` opts in: Chrome 146+ (desktop, but effective on mobile only for now), Chrome for Android 156; Edge 146+. It is undone by a fixed root/body font size in px, so the page must leave the root at the browser default (or a %), and `DomTextSize` must read the default before setting anything. `env(preferred-text-scale)` is the CSS-only equivalent. **D7: add the meta tag in WU3.** Safari, Firefox and Samsung Internet don't support it.
  - **Android Firefox:** follows the OS text size by itself, as a full zoom, px units included; nothing to do, and the layout sees a narrower viewport.
  - **iOS Safari:** `font: -apple-system-body` follows Dynamic Type (Safari 14+); 17px at the middle (standard) step, 13px on macOS Safari, which matches the same `font` keyword, so the probe must be limited to iOS/iPadOS (e.g. `-webkit-touch-callout` support plus touch). `rem` itself stays 16px on iOS whatever the setting (WebKit bug 260880), hence the probe. No published px table per Dynamic Type step for Safari; native body text reaches ~3x at AX5. The [human] iPhone check covers the steps.
  - **Pitfall:** sources disagree whether a `font-size` on the same element as `font: -apple-system-body` breaks the link; the probe is its own element with only that `font`, so it doesn't matter.
  - Sources: [Roselli, Honoring Mobile OS Text Size](https://adrianroselli.com/2026/02/honoring-mobile-os-text-size.html), [Tumath, Let's fix the web's text size](https://www.joshtumath.uk/posts/2026-07-02-lets-fix-the-webs-text-size/), [caniuse: meta text-scale](https://caniuse.com/mdn-html_elements_meta_name_text-scale), [WebKit bug 215279 (17px/13px)](https://bugs.webkit.org/show_bug.cgi?id=215279), [WebKit bug 260880 (rem ignores system size)](https://bugs.webkit.org/show_bug.cgi?id=260880), [CSSWG explainer: env(preferred-text-scale)](https://drafts.csswg.org/css-env-1/explainers/env-preferred-text-scale.md), [Puppeteer user-preferences plugin (pref key)](https://classic.yarnpkg.com/en/package/puppeteer-extra-plugin-user-preferences).

## Debrief summary

### 2026-10-29

**What went well**
- The split shipped the layout first (WU2, invisible at the standard size) and the text growth last (WU3), so the public site never had text outgrowing a fixed layout.
- The harness's `--text-size` (WU1) made the larger sizes measurable headless. At 200% it found two real layout bugs that 150% hadn't shown: step lines scrolling sideways, and a classic scrollbar leaving the 100vw-sized landscape app wider than the window. It also found two gaps in its own checks (a scrolled page read as tiles past the top; widths checked against `innerWidth`).
- The user's iPhone (Dynamic Type, accessibility sizes) and Firefox/Safari checks passed on the first try, and so did Firefox's Zoom Text Only after the audit's fix.
- The user called the overall run "quite fine" and the rest expected.

**What was hard or surprising**
- The audit's possible double scaling under Firefox text zoom couldn't be confirmed headless. It was fixed anyway by leaving the root alone when the browser default is already the target size.
- Full measurement runs took about 40 minutes. 6x6 solution queries wasted about 32 s per case and pushed a query past `measure.sh`'s 600 s cap. On 6x6 there's no Give Up and no Mordie by design, so those cases can't exist.
- Headless Chrome's screenshot mode captures before page timers run, so it couldn't show the game with the startup dialog closed.
- WU2's measurements and the round-1 audit's crossed on the harness's default port.
- The ship agent signed both intermediate release commits with its own Haiku trailer.
