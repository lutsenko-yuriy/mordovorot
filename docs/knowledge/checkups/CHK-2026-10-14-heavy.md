### Readability & structural clarity

- **Finding:** Small duplications. `defaultView` built an identical `ModeSwitcherImpl` lambda three times. `KeyboardInput` kept a private `DEFAULT_SQUARE_SIDE = 4` that duplicated `BoardSize.DEFAULT`. A `ScreenRenderer` comment still said "F5/F6/Esc" after F7/F8/F9 were added.
- **Debt quadrant:** inadvertent × prudent
- **Disposition:** fixed inline (commit `2c37860`)
- **Graduation candidate:** no

- **Finding:** `TuiView` (429 lines) runs four near-identical modal loops: `handleToolbarExit`, `runSaveDialog`, `runLoadDialog`, and `runSizeDialog`. Each one does the same `repaintWithDialog` → `input.onDialogEvent(terminal.readEvent(), …)` → `when` over `Cancel`/`Activate`/`Quit`, with `trackDialogCancelled` repeated on two branches. A shared modal-loop helper that takes a per-dialog `Activate` handler would shrink the class and make "every dialog tracks cancel exactly once" structural instead of copy-pasted.
- **Debt quadrant:** inadvertent × prudent
- **Disposition:** deferred — see ledger Open findings, deadline `2027-01-14`
- **Graduation candidate:** yes — detekt `LargeClass`/`CyclomaticComplexMethod` thresholds; a duplicate-code check (e.g. PMD CPD) would also catch the loop copies.

- **Finding:** The same three-armed catch appears in five places: `ViewModelImpl.saveGame`/`loadGame`/`restoreOnStartup`, `GameSession.run`, and `ViewImpl.play`. It rethrows `SessionControlException`, rethrows `CancellationException`, then handles `Exception`. A shared helper (e.g. `inline fun <T> catchingNonControl(onError: (Exception) -> T, block: () -> T)`) would remove the chance that a future call site forgets one of the two rethrows. Earlier audits (PR #37, PR #43) each caught exactly that omission.
- **Debt quadrant:** inadvertent × prudent
- **Disposition:** deferred — see ledger Open findings, deadline `2027-01-14`
- **Graduation candidate:** yes — detekt `TooGenericExceptionCaught`/`SwallowedException`, or a custom rule flagging `catch (e: Exception)` without a preceding `CancellationException` arm in a `suspend` context.

### Cross-surface UX consistency

- **Finding:** Solving the board behaves differently on each surface. The TUI shows `Congratulations ✓`, dims the arrows, and keeps the toolbar live. The console `ViewImpl.play` loop simply exits once `isSolved()` turns true: there is no message and the final, solved board is never even displayed, so the process just ends. PRODUCT_SPEC lists this as a known gap, but it is the main inconsistency between the console and the TUIs (Nielsen #1 visibility of system status, #4 consistency).
- **Debt quadrant:** deliberate × prudent
- **Disposition:** deferred — see ledger Open findings, deadline `2026-12-14`
- **Graduation candidate:** no

- **Finding:** Console error feedback is generic. Any malformed command, missing argument, or unknown verb prints `Incorrect input`, and shift-range errors print `Incorrect row`/`Incorrect column`. There is no `help` command, and nothing lists the available commands. Both TUIs show their controls on screen (toolbar, keyboard controls hint), so the console is the only surface where the player has to remember the command set (Nielsen #6 recognition over recall, #9 error recovery, #10 help).
- **Debt quadrant:** inadvertent × prudent
- **Disposition:** deferred — see ledger Open findings, deadline `2027-01-14`
- **Graduation candidate:** no

### Accessibility

- **Finding:** In keyboard mode the board cursor is shown only by changing the highlighted arrow's colour to bright yellow (`CURSOR_COLOR_ON`, SGR 93), with no shape, reverse-video, or bracket cue. On a monochrome or `NO_COLOR` terminal, or for some colour-vision deficiencies, the cursor's position cannot be seen (WCAG 1.4.1 Use of Color). Dialog focus already uses reverse video and the Load list uses a `> ` marker, so the board cursor is the odd one out. Context: the full-screen TUI is inherently hostile to screen readers (full repaints, box-drawing glyphs). Console mode is the accessible fallback, and it stays reachable mid-session via F8/`[ Console ]`, so that part is acceptable.
- **Debt quadrant:** inadvertent × prudent
- **Disposition:** deferred — see ledger Open findings, deadline `2026-12-14`
- **Graduation candidate:** no
